## What ships today

First-person stealth intrusion for WebGL (Chrome primary). Six rooms, played in order. Each room is one Unity scene, generated by LevelBuilder from `DESYNC/Assets/Scripts/Levels/RoomLayouts.cs`.

| # | Room | Scene | Terminals | Notes |
| --- | --- | --- | --- | --- |
| 1 | BOOT | Room_01 | 1 | Flip, and the walls vanish |
| 2 | EYES | Room_02 | 1 | Cameras; phase past the cones |
| 3 | ICE | Room_03 | 2 | Hunters; manage melt |
| 4 | HIJACK | Room_04 | 2 + hijack pad | Both layers lethal; hijack a drone |
| 5 | UNSTABLE | Room_05 | 2 | Glitch zones; 90 s TRACE countdown |
| 6 | ROOT | Room_06 | 3 shield terminals | Architect gaze; finale, no exit |

Scene order: Boot, then Title, then Room_01 to Room_06, then Ending.

## Core rules as shipped

- SPACE flips between RENDER and SOURCE. It is the only core verb.
- RENDER: walls are solid. Cameras and drones are active. Hunters are frozen and harmless.
- SOURCE: walls are passable. Cameras are blind. Hunters are active and kill on touch.
- A flip that would end inside a wall is refused.
- Melt: +12 %/s in SOURCE, -4 %/s in RENDER, +5 % per flip. Warning at 70 %. At 100 % the player holds 0.6 s, then dies.
- TRACE: a camera or drone cone holding the player for 0.5 s starts a 6 s TRACE. The third TRACE in a room is an alarm, and the room restarts.
- ICE vents spawn hunters only from time spent in SOURCE. Max 4 alive.
- Terminals: press E within 2.5 m, then enter the arrow sequence. A wrong key resets it after a 0.4 s lockout.
- Hijack pads run the same minigame and take a drone for 10 s.
- Glitch zones (room 5) count down 3 s, then force a flip.
- Failure: a 0.2 s REBOOT, then an identical restart. No death screen yet.

## Running things

Unity runs only through `tools/unity.sh`. A lock serialises runs, so expect waits.

- `tools/unity.sh compile <tag>`: import and compile. Prints `error CS…` lines.
- `tools/unity.sh exec <tag> Namespace.Class.Method`: run one static editor method.
- `tools/unity.sh test <tag> EditMode|PlayMode [filter]`: Unity Test Framework. Results land in `logs/<tag>-results.xml`.
- Logs: `logs/<tag>-HHMMSS-PID.log`. Unity exits 1 if any assembly has errors, so read the paths it prints.
- Never open the project in the Unity editor GUI while a batch run is active.

Builds and deploys:

- `tools/build.sh WebRelease|WebDev|MacRelease|WinRelease [--probe]` writes `Builds/<Profile>/`. It runs `BuildScript` through `unity.sh`.
- `tools/deploy.sh [--prod]` copies `Builds/WebRelease` into `web/site` and deploys it. Preview by default. Production only with `--prod`.

Not yet present: `tools/test.sh`, the local runner for all gates that `docs/DECISIONS.md` (D-007) names.

LevelBuilder (`DESYNC/Assets/Editor/Levels`) regenerates the room scenes. The LEVELS workstream owns that run, because it rewrites `Assets/Scenes`.

## Rules for this repo

- Work only in this worktree, `/Users/mac/Documents/Projects/gamethon-breach`. Edit only the paths your brief lists.
- Core (`Assets/Scripts/Core`, `Rules/Contracts.cs`) is frozen API. You may append one line at a time to `GameEvents.cs` or `GameState.cs`.
- No `git` commands that change state.
- Zero GC allocations per frame. Pool everything.
- Read tunables from `GameState.Mods` where it covers them, otherwise from `GameConfig.I`. Do not hardcode.
- Randomness only through seeded `Mulberry32` substreams. No `System.Random` or `UnityEngine.Random` in Rules or Gen (test RNG-04).
- Scores are never trusted from the client. The server recomputes them (M4).
- Juice caps: shake at most 0.35 units, hit-stop at most 90 ms, chromatic peak at most 0.6, full-screen flashes at most one per 2 s. Respect Reduce FX and Reduce Flashing.
- Every bug report or replay carries seed, build hash and save version.
